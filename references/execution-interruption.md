# 执行中断分类与接续（认证失败 / 权限拒绝 / 字段合同 / 隔离输出 / 等待与报告）

本文件是主脑与执行 Agent 在任务中断时的流程决策规则（BW-INTERRUPTION-20261015-S1，2026-10-15）。触发背景为客户三轮报告中出现的三类中断：真实认证失败、批量权限拒绝、以及字段类型合同缺失。本文件只改变流程决策，不新增任何自动拦截、定时轮询、全局健康状态机、schema 或表；所有原始证据（原文错误、exit code、原始工具结果）必须保留，不得由摘要替代。

## 1. 认证失败（auth failed）与额度/权限分型

- 调度层 `eligible` / capacity claim 只是**资格**，不等于模型真实调用成功。真实认证错误（如 "Custom model authentication failed. Please check if your API Key is correctly configured and valid."，exit 1）必须与 quota/限额、权限、台账、报告格式错误分开分型；错误原文与 exit code 原样保留，只确认 auth failed，**不断言密钥已失效**（后台不能读取或修复密钥，真因需用户侧核验）。
- 认证未修复时，**当前接续任务内**不重复同一 `runtime:model`/同一 config 版本；不连坐同 executor 的其他模型（如 CN 内置 Max），也不连坐 CN 内置之外的整个 executor，不删改用户完整授权候选集合，不把 auth 错误写成 quota/限额标记。
- 保持**一条**简短失败记录指向证据路径与终态；确认 writer 进程已退出、容量名额真实释放后，从**已授权且当前实际可用**的候选中重选接续；本任务内已有的临时失败记录可复用，不新建全局持久健康机制。
- 只有在用户修复配置后或用户明确要求核验时，才对该组合做有限次数的重新尝试；候选重新可用也不得宣称等于真实调用成功。
- 容量池对该接续有程序化执行（BW-CONTINUE-20261019-S6）：本轮真实失败过的 `runtime:model` 由主脑
  记入票据 scope 的 `luna_preauthorization.round_failed_candidates` 后，`claim_due` 的国内回收**不会**
  把刚失败的候选重新认领（299 秒腾出空位也不行）；只有本任务受信任候选全部不可用或满载且客观核验通过
  时，固定 300 秒无回复才按原单接续 Luna（299 仍不 claim、300 Luna 单赢家）。该接续只对本任务、
  这一次有效，不是全局/永久 Luna 授权；用户主动暂停/取消/删除任务与 `cancel`/`external_agent`/
  `domestic` 回复绝不因预授权派 Luna，原始失败记录保留、不假恢复。机制详见
  [全局并发容量池](global-dispatch.md) 的"任务级 300 秒 Luna 预授权与本轮失败候选接续"一节。
- 若规划器/调度输入无法表达"auth 排除"，如实写出该限制与原始 auth 证据，**不得**改写为假限额或伪称 AUTO 已过滤；确实没有已授权且真实可用的候选时询问用户，不自动切 GPT/Luna。

## 2. 权限拒绝（permission denial）

- **派发前**把本轮目标实际需要的工具与当前配置的 allow/deny 逐项核对；调度层 `eligible`/路由资格只代表候选可被选择，不代表所需工具已配置或已获授权。
- 出现权限拒绝时立即停止受影响动作及其同义命令变体、反复 Edit 与 Edit→Write→Bash 等**同义替代**；保留被拒工具、目标、原命令、错误原文与次数及处置结论。
- **当前调用停止与用户任务停止分开**：客户端/适配器停止有问题的调用，不给用户任务自动判终止。先确认原 writer 真实终态、保存部分成果和原拒绝，再继续已有授权覆盖且不依赖被拒权限的工作；受阻路径明确列出，不以故障报告或内部台账代替业务交付。
- 若已确认是客户端配置与用户已有授权不符，可在该授权内修正配置、独立验证后接续，不要求用户重复批准同一动作；配置核验通过不等于真实 CLI 执行成功，未查明根因时如实保持未知。用户最新授权允许的 Claude 默认直接模式不被旧 dontAsk 配置覆盖；报告里的旧模式只作当时证据。
- 真实宿主/系统审批拒绝、权限归属不明或原进程仍活/未知时，不换工具、入口或执行器绕过；仅阻塞依赖它的动作。没有可继续的授权路径时才说明具体外部依赖，不笼统要求用户处理整项任务。GPT/Luna 接手仍须已有明确授权。
- 主脑验收**必须读取原始工具结果与会话/事件流**，不能只看 `permission_denials` 汇要或 exit 0 就放行；汇报中要写清原始拒绝数量、被拒目标、未完成动作、后续处置与接续方式。
- 最终报告写“失败无/越界无”不能抹去拒绝链；普通工具错误或非必需动作被拒可如实归因，不机械等同整个业务失败，但相关拒绝事实仍须并列保留。
- 权限拒绝不得通过更换执行器绕过；也不因一个被拒的额外 `ls` 泛化否定整个测试能力。
- 已实现的 Claude/CN 监视仅针对本轮调用，不决定用户任务终态；其他流程要求不冒充已实现的自动杀进程或即时拦截能力。
- CN 传输层例外（BW-CN-PERMISSION-STOP-20261015T155930Z-S1/S3，范围仅 `scripts/qoder_direct.py`
  的 `--runtime qodercn` 分支 + `scripts/qoder_permission_watch.py`）：CN 直连入口现实现**有界
  机械监视**——Popen 前静态拒绝裸/整工具通配 mutation allow 规则（要求逐文件 `Edit(...)` 与
  `Bash(原样命令)`），运行期经官方 `--session-id` 按现场路径
  `projects/<workspace-key>/<精确sessionId>.jsonl` 只读增量读取本会话原生 jsonl，只认 sessionId/cwd
  绑定的 `type=user` tool_result 且**事件顶层/块内**结构化 `toolDenialKind=permission-rule`、或工具
  结果**起始处**直接构成的固定拒绝文案（允许可选 `Error:` 前缀；输出中间引用同一句不误停），即经
  本次 Popen 对象终止并等待真实退出；终态不明确保留 unknown 占位。这不改变本节流程纪律：CN 所有
  已知终态都随 `summary.cn_watch_facts` 留本轮监控事实（是否找到/观察到会话、degraded、错误与读取
  进度；未找到即 `session_observed=false`，绝不冒充已观察），监视按约 0.2 秒轮询属非零延迟、读错只
  记事实不冒充保护、不承诺零后续工具竞态；主脑验收仍必须读原始工具结果与会话流（最小拒绝证据在证据
  目录 `permission-stop.json`，原始会话文件不改）。实现与边界见
  [Qoder CN 本机原生直连](qodercn-direct.md)；Claude 另有 stdout 首次拒绝监视，见 [Claude 直连](claude-direct.md)，不得继续称其他执行器均无监视。

## 3. 真实字段合同（外部接口字段类型）

- 含外部接口的任务，必须依据**当次真实的 schema / 官方可用合同**核实字段类型，不把历史业务例子固化为通用字段清单。
- 假接口（stub/mock）校验必填字段类型、shape 与序列化后的请求内容；错误类型也应被断言拒绝，而不是只断言存在即通过。核对**实际发出的 payload**，不能只看页面/响应绿测。
- 样例套号、多选等结构可能各自需要不同类型；schema 未知时明确阻断对应业务的完成判定，不能猜。未做真实写入不得宣称外部保存成功。

## 4. 隔离测试输出路径审查

- 隔离测试启动前审查所有输出路径（截图/快照/日志/下载/缓存），包括硬编码绝对路径、环境变量、运行 cwd 与导入副作用，全部重定向到本次隔离目录。只拷源码、换 cwd 不够；无法改输出路径时先不执行写入型测试，并说明精确阻碍点。
- 普通工程不强制逐文件 hard grants 或 OS 沙箱；普通 ZCode 整工具 Bash 仍允许，其范围与技术沙箱分开评价。
- 写后用受保护产物的哈希或限定文件清单比对验证越界；未列目录不能宣称"绝对零变更"。发现越界先保留证据、核对影响，不擅自覆盖恢复。

## 5. 等待与报告纪律

- 观察重复拒绝、同样错误、长时间无新真实产出时尽早识别无效循环，不设机械固定分钟数，也不自动终止用户要求继续等待的原报告。
- 只汇报已变化的有效进展、新阻断或需要用户输入的事项，不因每次轮询刷新状态。
- 不为报告格式重做已验证的工程；部分代码与文件哈希、原始报告、真实测试绑定保留。
- 故障单独醒目报告；未委托业务对话修 Skill 时只交接故障，不把技能升级或内部流程收尾插到业务交付前。规划快照的 runtime/model 与实际启动参数逐轮核对；需要改道先重新裁决并记录原因，不声称旧快照就是实际选择。
- 状态提问回答后继续原授权目标。短故障链集中在必须相邻的路径、可信输入与剩余阻断上，区分代码测试 / 生产加载 / 真实业务验收，不无限扩大完整链，也不把每个漏项拆成新的成功阶段。

## 5.1 凭据消费、敏感输入与日志范围

- Agent 工作副本只放必要源码与合成配置；不把 `.env`、私密输入或密钥全文交给 Read/提示词/聊天。宿主若确需消费敏感真实接口，应在**另一个不暴露给 Agent 的验证上下文**中使用最少凭据，只向 Agent 返回状态码与脱敏字段。此处**不新造重复审批**：先核对已有授权，已覆盖的必要验证、可逆保护与脱敏材料可继续进行，只有缺失的具体敏感动作授权才询问用户。
- 仅把 secret 放进 Agent 环境变量仍可能被 Bash、Read 或日志暴露，不能当作完整防护；本 Skill 不宣称已实现通用 OS 沙箱、自动日志脱敏或 secret broker。
- 日志可能含凭据时，不把原日志整份转给新 Agent、写入公开提交或项目笔记；保留受限原件，公开材料只引用脱敏索引与哈希。保护、轮换、删除凭据或原件按**已有授权与副作用边界**处理，不因本 Skill 修复自动做：已授权覆盖的可逆保护与脱敏材料可继续，只有缺失的具体敏感动作（轮换/删除/外发）授权才询问，不自动改动密钥或原始日志。本 Skill 也不宣称已修复历史 OCR 密钥事故（见上：未实现 OS 沙箱）。

## 6. 桌面可复核验收场景（流程预期，非已实现门禁）

以下为流程验收场景，供桌面复核本文件决策；不声称已动态实现门禁、也不声称已跑过业务测试：

1. **eligible + auth 失败**：调度 claim 成功（eligible）但真实调用返回认证失败 exit 1 → 分型为 auth（实现口径：只有真实结构化失败错误载体 result_errors/result_errors_info 中的明确认证失败文案（如 "Custom model authentication failed."）才由 diagnose 映射为 `authentication_failure`，该映射仅经离线合成样例验证；无自动 auth 过滤/路由，也未做真实认证恢复验证），不写 quota；本任务内不再重试同组合；名额释放后在已授权候选中重选。
2. **21 次拒绝但 exit 0**：报告 exit 0 且 `permission_denials` 计数 21 → 主脑读原始工具结果，核对被拒动作是否为必需动作、以及是否后来在同一授权内补齐证据：若被拒的是非必需动作且必需动作已证实完成，可按业务验收放行，但拒绝次数与处置仍须披露；不单凭 exit 0 放行，也不因存在任何拒绝就机械判定整体失败。
3. **字段 shape 错误但假 API 返回成功**：stub 接口对错误类型字段仍返回成功 → 验收要求 payload 类型断言失败被暴露，不得宣称外部保存成功。
4. **隔离截图指向正式目录**：隔离测试截图落盘路径在正式目录 → 判定输出路径审查缺失，测试需重定向后重跑或如实阻断。
5. **已有报告等待授权**：报告已产出但后续动作需用户授权 → 保持等待，不自动终止、不重复轮询刷状态。
6. **普通 ZCode 工具不缩权**：普通工程的 ZCode 整工具 Bash 使用不因本文件被限制；只有技术沙箱隔离场景才按第 4 节收紧。

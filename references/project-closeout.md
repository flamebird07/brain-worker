# 项目收尾清单

首次规划和最终回复前，在**同一份现有任务记录或验收报告**中填写、更新以下清单；不另建调度系统、状态库或授权开关。清单只核对执行事实，不授予推送、生产操作或外部写入权限。

结束状态：`业务待验收 → 业务验收通过/收尾中 → 整体完成`。业务待验收也涵盖尚未执行或尚未验收通过的任务。业务通过后，仍有适用必选项待办、执行中或阻塞，就保持收尾中并推进已授权部分；外部阻碍无法自行解决时，如实报告“业务完成，交付未完成”。只有适用必选项已验证或客户明确排除，才能整体完成。不适用项须说明具体理由，空值不能当作完成。

## 复用清单

每项状态只取：`待办 / 执行中 / 已验证 / 不适用 / 客户明确排除 / 阻塞`。规划时记录适用性、已有授权来源和预期证据；结束前回填真实证据、未完成动作与阻碍。不得为了清单全绿把阻塞改成不适用。

| 项目 | 状态、适用性及授权来源 | 已验证依据或剩余动作 |
| --- | --- | --- |
| 业务验收 | 待填写 | 锁定目标与范围、独立验收结果、必要测试和剩余边界；测试须对应最终产物 |
| 生产加载 | 待填写 | 实际加载证据；每次新建子进程读盘时，以调用链说明无需重启；无生产加载需求可记不适用并说明原因 |
| GitHub | 待填写 | 正确仓库、目标分支、精确文件范围、完整提交SHA，以及推送后远端目标分支回读一致；本地commit或push退出0不够 |
| Obsidian | 待填写 | 已有项目笔记绝对路径，写后回读正文及链接；无相关记录需求须说明不适用理由 |
| Agent收口 | 待填写 | 原始报告/失败证据、每轮结果与独立验收、真实终态及容量释放；在途或退出未知不算收口 |
| 能力台账 | 待填写 | 本任务适用后端的持久记录与回读；缺配置如实阻塞/待记录，不借用其他任务例外、业务凭据或伪造同步 |

客户明确排除某项时，记录原话及作用范围，继续其他适用授权项。缺推送等具体授权时，先完成只读核对和可审核准备，仅询问该动作；不因此停掉其余已授权收尾。清单不要求默认重启生产、推送所有文件或接入新凭据。

返工、报告格式修复和补收尾归原事件，不增加业务成功样本；评分沿用原阶段事件ID。实际新派发仍按既有逐轮规则计入来回总数，保留失败、阻塞与补修轮，不能只列成功轮。主脑直接接手注明实际执行者，不冒充外部Agent报告。

## 最终回复简短模板

```text
业务结果：实际验收结论与边界。
生产加载：已验证 / 无需加载及理由 / 未完成。
GitHub：目标分支与远端完整SHA回读 / 排除 / 未完成。
项目记录：既有笔记写后回读 / 排除 / 未完成。
Agent收口：实际总轮数，每轮目标、结果、验收；在途或未知另列。
台账与未完成项：持久回读 / 阻塞及原因，下一步及缺失授权。
```

## 九个流程验收场景

以下是规则审查场景，不是已运行的软件测试或生产演练；实施时逐项核对实际记录，不从示例制造完成凭据。

| 输入状态 | 正确下一步 | 不得得出的结论或动作 |
| --- | --- | --- |
| 1. 代码验收通过，已授权GitHub/Obsidian待办 | 保持收尾中，继续两项收尾 | 代码通过即整体完成、等待客户催促 |
| 2. 本地commit或push成功，无远端回读 | GitHub执行中，回读目标分支完整SHA并比对 | 命令成功即远端已验证 |
| 3. 笔记写盘，未回读 | Obsidian执行中，回读正文与链接 | 写盘即记录已验证 |
| 4. 客户明确排除一项 | 记排除及具体理由，其余适用授权项继续 | 扩大为全部收尾排除、重复问已排除项 |
| 5. 没有推送授权 | 准备精确可审核范围，只询问推送，继续其他已授权部分 | 清单自动授权push |
| 6. 每次新子进程读盘，无需服务重启 | 用调用链说明无需重启，按适用性记录 | 为形式收尾打断生产，或无证据声称已加载 |
| 7. 能力台账缺配置 | 如实阻塞/待记录，不假称同步，业务与交付状态分开 | 借用另一任务台账例外、伪造成功、停止其他已授权收尾 |
| 8. 首轮验收失败，补修通过 | 记录两轮与各自验收，评分归原事件 | 只列成功轮、重复增加成功样本 |
| 9. 适用收尾全部有证据，原始报告已收口 | 核对无必选未完成项后整体完成；不适用/排除说明理由 | 省略必选项、无凭据填成全绿 |

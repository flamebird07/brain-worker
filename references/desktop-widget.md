## 最简单启动

```text
pythonw scripts/worker_status_widget.py
```

`pythonw` 无控制台窗口；用 `python` 也可以。可选参数：

- `--store <路径>`：显式指定调度池 SQLite。缺省沿用 `dispatch_pool` 的权威默认
  （`~/.brain-worker/dispatch-pool.sqlite3`，`BRAIN_WORKER_DISPATCH_STORE` 环境覆盖）。
  路径不存在时如实显示“读取失败 · 待核”，**绝不建库/建表**。
- `--interval <秒>`：刷新间隔，默认 2 秒、最小 1 秒。
- `--once`：不启动 GUI，只读取一次并输出安全 JSON（不含 token/prompt/argv/秘密），
  供主脑/脚本做真实只读验证；快照不可用时退出码 2。

桌面双击入口（`.bat`/快捷方式指向上述 `pythonw` 命令）、真实本机启动与截图验收由
root 阶段完成；本文件只登记启动方式。

## 数据从哪来

数据只来自**跨对话共享的调度池 SQLite**（`dispatch_pool` 的 attempts 等既有表），
经 `stage_selection._open_store_ro` 的 `mode=ro` 短事务只读快照——与阶段规划入口同一
套拒绝语义：缺库、缺表、被锁定、WAL 存在但缺 `-shm` 都如实拒绝/待核，绝不创建
sidecar、绝不 migrate、绝不回落成空表冒充空闲。

浮窗**不直接探测任何模型、不查余额、不扫原始日志**；“每 2 秒更新”只是定时重读这份
本地数据库快照，不是每秒抓日志或轮询外部系统。

### 刷新与数据源核对

- GUI 启动时按 `--store` > 本进程继承的 `BRAIN_WORKER_DISPATCH_STORE` >
  `~/.brain-worker/dispatch-pool.sqlite3` 解析并固定绝对路径。底部页脚（本地只读状态 +
  数据源路径及来源）只在**展开态**显示；精简态（无行/有运行行/读取失败）整段页脚不参与
  布局，但文本仍保留在控件中，单击展开即按原内容显示。`--once` 使用同一默认解析函数，
  但它是另一个进程，可能继承不同环境；应将 JSON 的 `store` 与窗口路径核对。
- Windows 单实例命中时，新启动直接退出，不向旧窗口转交 `--store` 或环境变量。
  修改终端环境、重复双击或执行 `--once` 均不能证明旧 GUI 已切换数据源。
- 后台顺序执行只读快照、入队、等待 2 秒；Tk 主线程首次 80ms、之后每 150ms 排空
  队列，只应用最新快照。有真实 `display_state=running` 的 Claude attempt 时，
  `view_rows` → `_set_rows` pack 行卡 → `_apply_mode` pack 行区 → `_fit_window`
  更新几何；真实结束后撤行，不延长运行态。两次消费间已结束的运行快照不会回放。
- 2 秒是后台等待间隔，不是端到端刷新时限：还包含读库、PID 探测及 Tk 主线程耗时
  （只读连接的锁等待上限为 30 秒）。页脚“已应用”是界面处理时间，不是历史截图
  或用户实际看见的证明。GUI 回调异常显示 `render_failed` 待核并撤下旧运行行，
  `finally` 保持下一次消费续调；不展示异常原文，不写池、不释放占位。
- 2026-10-24 有界回归使用隔离 SQLite、注入 PID 探针和独立隐藏 Tk 窗口驱动生产
  回调，覆盖 Claude idle→running→finished、队列只取最新、异常恢复和数据源常驻。
  确认的是当前刷新链路与异常续调缺口；13:18:20 的 `--once` running 读回只证明
  当时共享池可见。没有历史 GUI 截图、环境或回调异常证据，不能认定这些缺口就是
  COOKIE-FOUR-REPAIR-20261024/F3 的历史根因，也不能用事故后代码或进程倒推。

## 界面语义（重要：显示 ≠ 业务验收）

- 行状态：**运行中 / 已预留（排队）/ 待核实 / 空闲 / 时段外**。
  - 占用计数以 attempts 表 `reserved/running/unknown` 为权威：子进程死了、PID 复用、
    创建身份对不上都**仍占位**，浮窗绝不代替 reconcile 释放名额。
  - **主行状态绝不只信 DB `running`**（BW-WORKER-WIDGET-20261018-S3 root 审查修正）：
    只有探针确认「活 PID + 创建身份匹配」才显示运行中；死 PID、PID 复用/身份不符、
    探测失败/未知、running 却未绑定子进程，主行一律显著「待核实」。同池混合时
    **待核优先**，绝不被另一个真 running 掩盖成绿灯。`reserved` 未绑子进程仍如实
    显示「已预留」；Luna 原生行不套本机探针。DB 原状态在详情里如实回显，占位计数不变。
  - “待核实”表示**本机进程状态未知或身份不明**，是诚实的不确定，不是业务裁决。
  - “时段外”只表示该池当前不接受**新派**（三 Qoder Max 北京夜间窗 / Claude 空闲时段
    门）；已有在途任务照常显示，绝不被时段遮盖。BW-OPENCODE-20261019-S4 起时段外行的
    展示文案富化（**仅显示层**，不改时段门/容量/派工/关机行为，也不改“运行中/待核实优先”

## 空闲自动关机（BW-WIDGET-IDLE-20261018-S2）

- 展开视图的勾选框「空闲30分钟自动关机」：**默认不勾选、不持久化**，关闭或重启
  浮窗即停用。勾选后**从当刻开始**，连续 30 分钟“有效空闲”才关机，界面显示剩余
  时间；取消勾选立即取消计划。精简视图仍显示已开启的计时（如 `空闲关机 29:59`；
  暂停时显示 `计时暂停`，到期复核显示 `复核中`），单击标题栏展开后可在勾选框随时取消；
  展开/折叠本身绝不勾选/停用/重置 controller。
- “有效空闲”= 只读快照 ok、字段齐全、未过期，且**无任何在途**——国内 16 名额、
  Luna、退休池的 `reserved/running/unknown`（含 PID 身份待核）都算在途，一律不关机；
  活任务结束后**重新计满 30 分钟**。
- 为不漏掉两个刷新间隔内开始又结束的**短调用**，`read_snapshot` 在同一个既有
  `mode=ro` 只读事务内附带最小活动签名（attempts 的 MAX(rowid)/COUNT 与最近
  reserved/started/ended 时间；不输出 token/prompt/错误正文）。签名变化即重置计时，
  绝不只看 `active==0`。
- 读取失败/字段缺失/快照过期 → 暂停并清零；恢复后必须重新完整 30 分钟，**绝不用
  旧绿灯关机**。倒计时用 monotonic 时钟，不受系统时钟跳变影响。
- 到期不直接关机：先**同步取得一份新只读快照最终复核**（无在途且活动签名未变化）
  才触发；复核发现突然来任务/签名变化/读取失败 → 放弃并重新计时。
- 真实动作只有一个：系统既有 `shutdown.exe /s /t 0`（**不加 /f、不重启、不执行任何
  业务动作、不动别人安排的关机**），且只由 Windows 用户勾选到期后的 GUI 路径触发；
  import、`--once`、未勾选、关闭浮窗都不会触发。无需额外守护服务或开机自启。
- 成功后**至多触发一次**；系统动作失败 → 界面显著显示失败并自动解除勾选，绝不
  每 2 秒无限重试（重新勾选视为用户新一轮授权）。控制器为纯逻辑（时钟/关机回调/
  UTC 均可注入），测试全部注入 mock，绝不真跑 shutdown。

- **默认精简、单击切换（BW-WIDGET-CLICK-COMPACT-20261029）**：初始为精简态。展开/折叠

  高度按内容动态计算并夹紧在当前屏幕内。**完整内容优先**：底部贴边时展开整体上移
  （标题 y 可变），展开即显示当前快照的全部可见行，绝不为固定标题裁掉行；右边贴边时
  向左夹紧，保持稳定与可关闭。
- **紧凑收回高度恢复（BW-HOVER-REPAIR-20261019-S6）**：布局重排由模块级
  `apply_layout(frames, expanded, has_rows, idle_compact)` 统一决定各区块 pack。用户
  现场发现：模型行隐藏后外框尺寸没恢复（Root 真实 Tk 复现：展开 710、行隐藏后仍

  实际窗口高度恢复到紧凑内容需要的高度；有一条或多条运行行时 `rows_frame` 正常参与

  点击事件、数据、调度、关机或模型顺序。真实 Tk 高度回归见 `TestRealTkLayoutHeight`

- **置顶/关闭**：`置顶:开/关` 切换总在最前；`×` 在精简和展开两种模式都可见，**仅关闭

# Brain Worker Desktop Entry

ZCode 桌面端与 Qoder 桌面端共用的**同一份**入口，安装到两个宿主目录的内容字节相同。实际调度、容量、优先级、时段、限额和执行器入口全部继续使用同一套 brain-worker 引擎，本文不复制任何可漂移的规则。

## 引擎位置

引擎根目录（安装时写入的本机绝对路径，两个宿主相同）：

```text
{{BRAIN_WORKER_ENGINE_ROOT}}
```

下文 `<engine_root>` 一律指这个绝对路径。启动时确认以下文件存在：

- `<engine_root>/scripts/stage_selection.py`
- `<engine_root>/scripts/dispatch_pool.py`
- `<engine_root>/scripts/dispatch_mode.py`
- `<engine_root>/scripts/worker_status_widget.py`

缺文件时明确报告桌面入口未正确安装，不猜路径、不新建另一套状态库。宿主应用不提供统一的技能目录环境变量，因此路径在安装时烘焙为字面值，不在运行时探测。

新会话用 `/brain-worker` 调用，也可在与本技能描述匹配的任务中由宿主自动加载。

## 宿主识别与本宿主禁用集

这是本文**唯一**承载的宿主特有信息：本宿主自己不能派发哪些牛马。识别在运行时完成，安装期不分叉。

按下列信号判定当前宿主，取第一个命中的：

| 宿主 | 识别信号（环境变量存在即命中） | 本宿主不可派发的精确组合 |
|---|---|---|
| Qoder 桌面 | `QODER_CONFIG_DIR` 或 `QODERCN_CONFIG_DIR` 或 `QODER_PRODUCT_ID` | `qoder:Qwen3.8-Max`、`qodercn:Qwen-3.8-Max`、`qodercn:Qwen3.8-Max`、`zcode:GLM-5.3`、`qoder:Sonus` |
| ZCode 桌面 | `ZCODE_SKILL_DIR` 或 `ZCODE_DESKTOP_CONTEXT_PROMPT_ENABLED` 或 `ZCODE_APP_VERSION` | `zcode:GLM-5.3`（宿主不递归自派自己；BW-ZCODE-RESTORE-1-20261022 起该组合恢复为引擎正常可派主力，故须显式排除） |

**无法确定宿主时必须 fail-closed：排除上表全部组合的并集**，并在回执中说明宿主未识别。绝不默认放行、绝不猜测宿主、绝不因为识别失败而放宽候选。

构造本轮 `allowed_candidates` 时施加上表排除集，并在回执中记录 `host_excluded_candidates=[<本宿主实际排除的组合>]` 与 `host_identified_as=<qoder-desktop|zcode-desktop|unknown>`，防止宿主递归启动自己或占用本宿主不可派发的通道。

排除集只收窄本轮候选，**绝不修改完整授权集合**。未列入排除集的其余已授权组合照常可接受派发，仍由引擎按优先级、时段、容量和限额裁决。

## 共享派发三档（强／中／弱）

brain-worker 的派发档位是**全宿主共享的手动三档**：strong（强）、medium（中）、weak（弱），**默认 weak**。ZCode 桌面、Qoder 桌面与主脑宿主读的是**同一份**档位状态，不存在按宿主分叉的私有档位。

- 档位状态文件：`~/.brain-worker/dispatch-mode.json`（可用环境变量 `BRAIN_WORKER_DISPATCH_MODE_FILE` 覆盖）。浮窗手动切换后原子保存，**只影响之后的新派发**；已在途的任务绝不中断、追杀或改派，按原状态自然结束。
- 缺文件、损坏 JSON、非法值或不可读路径时**安全回落 weak**，回执如实报出来源与错误短码，绝不把读取错误冒充成用户选过的档位。
- 各档允许哪些精确池、按什么层序、受哪些时段门，**唯一数字来源是 `<engine_root>/scripts/dispatch_mode.py`**（`dispatch_pool`/`stage_selection`/浮窗统一消费，每次裁决现读）。本文不抄写任何池清单、层号、时段或容量数字；桌面宿主需要细节时读引擎代码或浮窗只读输出，绝不凭记忆复述。
- 档位与守卫正交：限额短窗、容量、总守卫、工作区单写、权限门、失败轮转、Luna 禁用全部照旧；时段门依赖异常时按 fail-closed 处理（当作窗口关闭，绝不当作放行）。

## 其余规则一律以引擎为准

优先级顺序、主力时段门、各池容量数字、池 key 清单、额度门禁、并发容量与在途保护，**全部由 `<engine_root>/scripts/` 下的共享代码强制执行，本文不重述、不摘要、不举例**。三个宿主调的是同一份代码，改一次全部生效；在本文里抄一份只会制造漂移。

- 共享状态与浮窗：`<engine_root>/scripts/worker_status_widget.py --once` 的只读结果。
- 阶段选择：`<engine_root>/scripts/stage_selection.py`。授权范围、工作区、权限需求和本轮失败候选必须来自当前任务事实。宿主排除集由本文在构造 `allowed_candidates` 时施加，该入口没有对应的命令行开关。
- 正式派发：只用所选执行器已有的正式 `*_direct.py` 入口。先读该入口的 `--help` 和 `<engine_root>/references/` 中对应文件，再构造参数；不凭经验混用 `--tools` 与 `--allowed-tools`。
- 执行器约束细节按需读取 `<engine_root>/references/`。不要一次性读取完整的大型主 Skill，也不要把历史事故段落当成当前状态。

派发前若规划回执显示某候选的入口运行时在本机缺失，如实报告该事实并按引擎裁决继续，不私自重装运行时、不改私有入口配置、不凭猜测改指向。

## 每轮必须遵守的行为约束

以下几条是宿主行为规范，在共享代码里没有强制点，因此必须在此保留；它们与 canonical 主 Skill 同源，由测试守卫防止静默漂移。

1. 每轮正式启动前必须向用户显示：`本轮牛马：执行器／请求模型；阶段目标；状态：准备派发。` 真正提交后显示“已提交”；预检拒绝则显示“未派发”和原始原因。
2. Luna 已删除并强制禁用，任何容量或等待状态都不得启动 Luna。
3. 只保存真实证据：request、进程终态、原始 stdout/stderr、报告、工具事件和产物回读。模型自述、退出码 0、格式合格或测试数量都不能单独证明工程完成。
4. 首次权限拒绝即停止当前受影响调用并保存证据；在已有授权范围内修正配置或重新裁决，不把内部错误升级成整个用户任务暂停。
5. 独立核对实际改动、必要测试和业务结果。状态询问、故障报告和阶段复盘不能取代原目标；用户任务未完成时继续处理已有授权且可行的部分。
6. 用户中途插话入队不打断：派发后本会话空闲时处理插话并把结论固化到 todo 队列；队列有可做项不空转停顿——任务未收尾而想停时必须先自问"为什么不做完、为什么不收尾"，答不出合法停点（后台任务在跑、或阻塞在只有用户能给的输入）就继续；互不冲突的队列任务按容量并行派工（编辑区重叠或同工作区则串行，同仓并行用各自 git worktree）。

桌面入口只负责调用既有引擎，不修改真实共享池来制造空位，不清历史错误，不查询余额，不复制或输出任何凭据。

## 验收与收尾

- 区分：模型已提交、工具实际执行、代码验收、生产加载、GitHub 远端、Obsidian 记录和能力台账。
- 业务验收通过后仍有适用且已授权的 GitHub、Obsidian 或安装同步时，状态保持“收尾中”并继续；远端完整提交回读和文档写后回读完成后才能说整体完成。
- 最终答复必须列出实际使用的执行器／请求模型、真实轮数、每轮结果、独立验收、未完成项，以及 `brain_worker=used`、`external_dispatch`。当前桌面会话自身工作不记作外部派工。
